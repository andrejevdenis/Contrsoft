# Тестовое задание на вакансию Тестировщик ПО, Контрсофт.
Исходные данные: 
Перед вами десктоп-приложение, которое является частью распределенной системы управления. Приложение отображает значения сигналов, полученных от удалённого сервиса через TCP-сокет. 
Главное окно содержит:
Таблицу сигналов (ID, имя, значение, качество, время)
Кнопку «Подключиться» для установки соединения с сервисом
Кнопку «Обновить» для ручного запроса значений
Сервис-симулятор (отдельный процесс):
Отправляет 10 сигналов с изменяющимися значениями (синусоида/случайные)
Работает на порту 2001

Условие задачи:
Задача для вас состоит из двух частей.

Первая часть — Составьте чек-лист для проверки приложения (не более 15 пунктов).
Вторая часть - Выберите самый критичный сценарий из вашего чек-листа (напишите, почему именно его).

Напишите автотест на Python (pytest) для этого сценария.
Код должен быть готов к запуску (с комментариями, объясняющими логику).
Добавьте проверку результата (assert).

## 📋 Чек-лист для проверки приложения

### 🔌 Установка соединения и сеть
* **Корректное подключение:** Нажатие кнопки «Подключиться» успешно устанавливает TCP-соединение с сервисом-симулятором на порту 2001.
* **Индикация статуса:** Интерфейс наглядно отображает текущее состояние сети (например, «Подключено», «Отключено», «Ошибка соединения»).
* **Обработка недоступности сервиса:** Приложение не зависает и выдает понятную ошибку, если сервис-симулятор не запущен или порт 2001 занят.
* **Внезапный обрыв связи:** Принудительное закрытие процесса симулятора корректно обрабатывается приложением (нет крэша, статус меняется на «Отключено»).
* **Повторное подключение:** После восстановления работы симулятора кнопка «Подключиться» успешно восстанавливает сессию.

### 📊 Отображение данных и таблица
* **Полнота данных:** Таблица отображает ровно 10 сигналов со всеми заполненными колонками (ID, Имя, Значение, Качество, Время).
* **Динамическое обновление:** При изменении значений в симуляторе данные в таблице обновляются в реальном времени.
* **Ручное обновление:** Нажатие кнопки «Обновить» принудительно запрашивает и актуализирует текущие значения из сокета.
* **Валидность типов данных:** Колонки корректно обрабатывают свои типы (ID — число, Значение — float, Время — формат даты, Качество — статусная строка/код).
* **Отображение качества сигнала:** Параметр «Качество» корректно реагирует на изменения (например, меняется на «Bad»/«Ошибка» при сбоях в симуляторе).

### 🖥️ Интерфейс и стабильность (UI/UX)
* **Блокировка интерфейса:** Потоковые сетевые операции выполняются в фоновом режиме и не замораживают UI *(Покрыто автотестом `test_network.py`)*.
* **Состояние кнопок:** Кнопка «Подключиться» блокируется или меняется на «Отключиться» после успешного соединения.
* **Сортировка и фильтрация:** Клик по заголовкам колонок корректно сортирует строки без потери связи с сокетом.
* **Поведение без связи:** Кнопка «Обновить» заблокирована, если соединение с TCP-сокетом еще не установлено.
* **Утечка памяти при нагрузке:** Длительная работа приложения не вызывает лагов и роста потребления ОЗУ.

## Самым критичным сценарием является «Блокировка интерфейса при сетевых операциях / Внезапный обрыв связи».
Если сетевой поток заблокирует главный поток UI (User Interface) при обрыве соединения, приложение «зависнет» (станет Not Responding). 
Пользователь не сможет нажать кнопку повторного подключения, закрыть программу или увидеть статус ошибки, что полностью нарушает работоспособность десктоп-системы

Репозиторий содержит автотесты для проверки устойчивости десктоп-приложения, отображающего технологические сигналы от удаленного сервиса через **TCP-сокет (порт 2001)**. 

Проект реализован на языке **Python**, использует фреймворк **pytest**, библиотеку **PyQt6** для эмуляции интерфейса и плагин **pytest-qt** для безопасного тестирования асинхронных событий UI.

#### Реализованный критический сценарий
* **Сценарий:** «Проверка отзывчивости UI при аварийном обрыве связи».
* **Цель:** Убедиться, что сетевые операции чтения/записи из TCP-сокета выполняются в фоновом потоке, а внезапное падение сервиса-симулятора не приводит к «зависанию» (*Not Responding*) графической оболочки приложения.

### 🚀 Быстрый старт

#### 1. Требования к окружению
Для запуска тестов необходим установленный интерпретатор **Python версии 3.9 и выше**.

#### 2. Установка зависимостей
Склонируйте репозиторий и установите необходимые библиотеки из терминала:

```bash
python -m pip install -r requirements.txt
```

#### 3. Запуск автотестов
Запустите `pytest` из корневой директории проекта. Флаг `-v` включит подробный (verbose) вывод:

```bash
python -m pytest Test/test_network.py -v
```

### 🧪 Описание логики работы тестов

1. **Setup (Инициализация):** Фикстура `mock_signal_server` из файла `conftest.py` в отдельном потоке инициализирует локальный TCP-сервер на порту `2001`, имитируя реальный сервис-симулятор.
2. **Action (Действие):** Тест создает инстанс главного окна `MainWindow`, с помощью утилиты `qtbot` имитирует клик по кнопке «Подключиться» и дожидается успешного статуса сборщика данных.
3. **Chaos (Эмуляция аварии):** Метод сервера `stop_and_drop_client()` принудительно отправляет `FIN`-пакет, разрывая TCP-канал (имитируя падение процесса симулятора).
4. **Assert (Проверка):** С помощью `qtbot` проверяется, что UI не заблокировался и корректно отработал событие дисконнекта, сохранив возможность повторного клика и взаимодействия пользователя с элементами интерфейса.
